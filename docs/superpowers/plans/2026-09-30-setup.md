# Vibecatch Bern – Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (gemäss CLAUDE.md, inline in dieser Session). Schritte mit Checkbox (`- [ ]`) abhaken, nach jedem Task committen.

**Goal:** Ein lauffähiges, leeres App-Gerüst mit eigener Supabase-Datenbank, eigenem Git-Repo und Vercel-Konfiguration, auf dem die Screens aufgebaut werden.

**Architecture:** Vite-SPA (React + TypeScript) mit Tailwind. Inhalte liegen hardcoded in `src/data/`, der Spielzustand in Supabase (nur über RPCs beschrieben). Dieser Plan liefert nur das Gerüst: keine Screens, kein Store, keine Auth-Logik.

**Tech Stack:** Vite, React, TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`), react-router-dom, zustand, @supabase/supabase-js, Vercel.

**Spec:** `CLAUDE.md` (Abschnitte „Stack“, „Env“, „Setup“, „Datenquellen“).

## Global Constraints

- Keine weiteren Libraries als die im Stack genannten.
- Keine Tests, kein i18n (CLAUDE.md hat Vorrang vor Skill-Vorgaben).
- Schreiben in die DB nur über RPCs; Schemaänderungen nur als neue Migration.
- `.env.local` und der Reset-Key werden nie committet.
- Supabase-Organisation: `vayemo gmbh` (`sarbtsqiphjvargdyntu`), Free-Plan, Region `eu-central-2`.
- Standorte sind Platzhalter „Standort 1“ bis „Standort 12“, Team-Zuteilung wie im Seed der Migration (1–3 → Team 1, 4–6 → Team 2, 7–9 → Team 3, 10–12 → Team 4).

## Review Focus

Ohne Tests werden diese Punkte von Hand geprüft (jeweils im genannten Task):

- Anonymous Sign-ins sind im Dashboard noch aus → RPCs schlagen später fehl. Hinweis an den User in Task 2.
- `.env.local` landet versehentlich im Repo → `git status` vor dem ersten Commit in Task 3 prüfen.
- Direkter Aufruf von `/reset` auf Vercel gibt 404 → SPA-Rewrite in Task 5, nach dem Deploy prüfen.
- IDs in `locations.ts`/`teams.ts` weichen von den DB-Tabellen ab → Abgleich per SQL in Task 4.
- Security-Advisors melden Befunde zur Migration → in Task 2 ausgeben, nicht stillschweigend übergehen.

- [ ] **Step 3: `src/data/locations.ts`**

```ts
export type Location = {
  id: number;
  teamId: number;
  name: string;
  shortName: string;
  image: string;
  topic: string;
  description: string;
  task: string;
  mapsUrl: string;
  x: number;
  y: number;
};

// Platzhalter, bis die finalen Standorte feststehen. IDs und Team-Zuteilung
// entsprechen dem Seed in supabase/migrations/0001_init.sql.
export const locations: Location[] = Array.from({ length: 12 }, (_, i) => {
  const id = i + 1;
  return {
    id,
    teamId: Math.floor(i / 3) + 1,
    name: `Standort ${id}`,
    shortName: `Standort ${id}`,
    image: `/images/locations/${String(id).padStart(2, '0')}.jpg`,
    topic: `Thema ${id}`,
    description: `Beschreibung für Standort ${id}.`,
    task: `Aufgabe für Standort ${id}.`,
    mapsUrl: 'https://maps.google.com/?q=Bern',
    x: 20 + (i % 3) * 30,
    y: 15 + Math.floor(i / 3) * 22,
  };
});
```
